# App 经验记录规范

仅在本轮产生可复用的新经验时读取并维护；执行任务时只需读取目标 App 的已有主题。

## 存放与复用

- 使用上下文明确提供的 Proma 工作区 `memory/`。先读取 `MEMORY.md` 与已有相关主题，复用同一 App/系统的文件；新主题默认放在 `computer-use/<app>-<platform>.md`，不创建空记录。
- 在 `MEMORY.md` 保留一条相对路径索引，注明 App、系统和适用任务，便于下次直接加载。记录属于当前工作区，不自动复制到其他项目或全局目录。
- 内置 Skill 只维护通用方法与随版本分发的默认路线。日常经验不能存入 `default-skills/` 或工作区内置 Skill 副本，否则升级可能丢失。
- 下次优先使用条件匹配的已验证路线；用户明确指定的方法优先。当前界面与记忆不一致时重新观察，旧经验不替代本轮证据。不要复用历史 PID、窗口 ID、element token、capture ID 或绝对坐标。

## 记录什么

按任务或操作命名条目，只保留会改变下次决策的信息：

```markdown
## <操作目标>
- 适用条件：App / 系统；已知版本、界面、搜索范围与焦点前提（未知项写未知，不为记录额外探测）
- 来源与日期：本轮实际观察或用户明确纠正；发生/验证日期
- 状态：已验证 / 用户提供（尚未实测）/ 待验证
- 推荐路线：最短有效步骤；每个关键节点如何判断成功
- 踩坑：在哪个状态做了什么，实际看到什么；已知原因或原因未知
- 恢复：从失败点如何恢复；哪些前置步骤已成功、无需重做
- 验证边界：只验证到哪一步；哪些系统、版本或后续动作尚未覆盖
```

按实际证据填写，省略不适用字段；不要为了套模板推测原因或编造验证结果。

## 如何迭代

1. **按步骤判断。** 一条流程前三步成功、第四步失败，只修正第四步及受影响的后续步骤。把前三步标为有效片段，不把整条流程标成最佳路线，也不把整条流程一概废弃。
2. **成功要有结果。** 以可见标题、搜索命中、焦点变化或实际保存结果验证目标；按键/API 返回成功不够。仅核对到联系人会话就不能宣称消息搜索或发送也已验证。
3. **失败要有条件。** 记录失败操作和可见症状，原因未知就写未知。一次焦点丢失、加载超时或过期截图不代表该 App 永远不支持某种操作。没有验证过的替代方案保持待验证，不能升级为推荐路线。
4. **合并而非堆叠。** 同一条件下的新成功证据补充已有条目；不同系统、版本或焦点条件分开写。明确区分新条件与冲突；发现冲突、需要删除或大段覆盖时遵循环境的确认边界，解决前不悄悄改写旧结论。
5. **控制记录范围。** 保留脱敏的操作方法和结果摘要，不保存聊天正文、真实联系人、账号、凭据或整段截图/OCR。临时阻碍没有复用价值时只在当前任务说明，不写长期记录。
6. **完成索引。** 主题和 `MEMORY.md` 同步做最小更新，保留已有用户内容；写后核对内容和索引链接。没有写入权限或写入失败时明确说未保存，不声称下次会记得。

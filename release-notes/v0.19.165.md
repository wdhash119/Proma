# Proma v0.19.165 更新

> 累积发布：包含 v0.19.161 之后至 v0.19.165 的全部变动（v0.19.162 / 0.19.163 / 0.19.164 / 0.19.165）。

## 新增

- **设置「磁盘管理」升级为「数据管理」** — 存储用量、数据清理、数据目录、跨设备迁移整合为一页；原「数据迁移」页整体并入（迁移原理、创建压缩包与恢复提示词原样保留），旧标签页状态自动映射到新页面。
- **数据目录整体迁移** — 支持把整个数据根（`~/.proma`）迁移到自选目录：预检（目标目录合法性、剩余空间、运行中会话）→ 复制 → 逐文件校验 → 写入路径指针 → 重启生效。旧数据默认保留，提供「删除旧数据」（二次确认，当前根缺少关键文件时拒绝）与「回滚到旧目录」；迁移同步改写会话索引、工作区索引与 Vault 配置中位于数据根内的绝对路径，迁移后会话续跑与孤儿判定不受影响。
- **过期孤儿数据清理** — 扫描 → 预览 → 确认清理，过期阈值 7/30/90 天可选（默认 30，按最后修改时间）。覆盖无索引引用的会话消息、无引用的 Pi artifact、孤立 spine sidecar、过期会话工作目录、Claude SDK 遗留目录（projects/、file-history/）；会话附件类目因引用关系无法确认只预览不删除。新增「启动时自动清理过期孤儿数据」开关，默认关闭。
- **Live Compact 压缩事件进入执行过程信息流** — 切割事件（spine_cut）现在持久化到会话转录，并作为过程行渲染在所属轮次的执行过程组内，按发生时间插回它对应的工具行之间（与工具调用同级同缩进，Scissors 图标 +「切下 N 段，节省约 X tokens」）；跨轮补发、找不到所属轮次的事件单独成行兜底显示，不再静默丢失。此前事件先被整批挑出追加到过程流末尾，看起来堆在信息流末端、读不出发生在哪一步。「显示压缩事件」开关统一控制实时与历史显示，关闭时压缩事件与 spine_recall 原文召回行一并隐藏。此前事件未持久化，开关对历史永远无效。注意：修复前已产生的历史会话无法回溯补齐，仅对新发生的切割生效。

## 优化

- **归档会话清理补齐实现** — 超过保留天数的归档会话同时删除消息 JSONL、Pi artifact 与 spine sidecar、会话工作目录（此前只删 JSONL，与页面文案不符）；索引条目保留，运行中会话跳过。
- **孤儿清理安全边界** — 会话工作目录按 UUID 命名 + 索引全量引用判定，memory/ 等非 UUID 目录结构性不会被触碰；清理执行时重扫并与预览路径取交集、删除前逐条重校验引用；破坏性清理接口在类型层面强制显式传入数据根，杜绝回退真实目录。

## 修复

- **协作续跑不再误报超时** — 父会话用 `continue_delegation` 给子会话追加指令时，桥接层原本按默认 2 分钟判定超时，稍长的续跑任务必然报「请求超时」而子会话其实还在继续。现在等待预算与工具自身的 1 小时上限对齐（另留 60 秒 IPC 余量），并真正响应取消信号：等待被取消或超时时立即返回「子会话仍在运行」，提示改用 `wait_for_delegations` 收敛结果。
- **测试运行不再泄漏空白会话** — 修复全量测试混跑时夹具会话（「默认内核会话」「Codex 会话」等空壳）写入真实会话列表的问题：Windows 下测试隔离同时覆盖 `USERPROFILE` 与数据根缓存重置，夹具永远落在临时目录。

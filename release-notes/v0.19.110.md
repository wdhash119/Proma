# Proma v0.19.110 更新

## 新增

- **模型能力手动设置** — 设置 → 模型配置中每个模型新增「模型能力设置」入口：自动检测（内置模型目录 / 名称推断）无法识别模型时，可按供应商文档手动指定上下文长度、最大输出、图片输入与推理（思考）能力。未识别模型在行内显示琥珀色「能力未识别」徽标，对话框内给出核对提示与各项自动检测默认值；手动值持久化到渠道配置，在 Agent 注册、思考档位与视觉助手路由中优先于自动检测生效。重新拉取模型列表或订阅重新登录会保留同 ID 模型的手动覆盖；数值留空、开关选「自动」即恢复自动检测，也可一键「恢复自动检测」。音频 / 视频输入不在运行时支持范围内（语音经「语音输入」转写为文本后发送），对话框内已注明。

## 优化

- **问答人设注入模式可选** — 人设管理中每个人设可选择问答注入模式：append（新建默认，基线约束 + 人设段落叠加，与 Agent 一致）或 replace（整体替换，旧自定义提示词迁移时默认保留原作者意图）。薄人设不再丢失基线约束。
- **侧栏顶部布局（非 macOS）** — Windows / Linux 侧栏顶部去除拖拽预留空白，首行控件直接顶着标题栏（标题栏本身可拖拽）；macOS 保留红绿灯避让，不与系统控件重叠。

## 修复

- **项目指令不再伪装用户消息重复注入** — 子树项目指令（如 `Proma/AGENTS.md`）此前每个新回合都会重复注入，且注入被 Pi 转成用户角色消息并在轮次结束后请求续跑：模型把注入当成用户发言、最终总结后还会多跑一轮，长轮次中诱发「用户反复重发」的自我强化计数。现在同一份指令（路径 + 内容哈希）每会话只注入一次，改为在下一轮开始前静默拼进系统提示词，不再产生用户角色伪装消息与额外轮次；文件内容变化按新哈希重新激活一次。legacy CLAUDE.md 迁移提醒的「每来源一次」守卫同样跨回合持久。
